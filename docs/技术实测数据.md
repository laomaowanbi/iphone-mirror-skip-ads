## 3. 移动窗口实测

| 操作 | 设置值 | 实际结果 | 结论 |
|---|---|---|---|
| 设 Position | `(0, 30)` | `(0, 31)` | ✅ 有效，y 有 1pt 系统偏移 |
| 设 Size | `(346, 762)`（还原原值） | `(341, 751)` | ⚠️ 系统重算，缩了 |

宽高比校验：`346/762 = 0.45407`，`341/751 = 0.45406` → **比例被锁定，只改内部尺寸**。

**决策：永不主动设 Size**，只固定 Position，坐标全部按相对比例换算。

### 菜单栏占用

```
NSScreen frame   = 2048 x 858
NSScreen visible = 2048 x 752, origin=(0, 76)
→ 顶部菜单栏 30pt，底部占用 76pt（Dock）
```
所以「左上角」实际可达位置为 `(0, 30)`，落到 `(0, 31)`。

## 4. 截图性能对比

| 方式 | 区域 | 平均耗时 | 输出 |
|---|---|---|---|
| `screencapture -x -R` | 85×24 逻辑点 | **98ms**（最快 92ms） | 170×48 px |
| `screencapture -x -R` | 整窗口 341×751 | 171ms | 682×1502 px |
| `CGDisplayCreateImageForRect` | 85×24 逻辑点 | **28.1ms** | 170×48 px |
| CGImage → numpy | 同上 | **~0ms** | shape (48,170,3) |

**采用 `CGDisplayCreateImageForRect`**，每 3 秒一次 → 每天 CPU 开销可忽略。

## 5. 「上滑继续看短剧」坐标测量

### 测量方法

1. 窗口截图（`ui_screenshot app=iPhone镜像`）：692×1524 物理像素 = 346×762 逻辑点（2.0×）
2. 灰度化后按行扫描亮像素（阈值 110），定位文字所在行带
3. 在行带内按列扫描，输出连续列段

### 原始扫描结果

行亮像素分布（物理 y）：
```
y=1416  bright=64     ← 文字上沿
y=1417  bright=97
...
y=1433  bright=130
y=1434  bright=54     ← 文字下沿
y=1435+ bright=36~53  ← 圆角/边缘（排除）
```

列分段（物理 x）：
```
(0, 27)      ← 窗口左圆角外的桌面背景（排除）
(257, 403)   ← 文字「上滑继续看短剧」
(417, 430)   ← 箭头 ⌃
(662, 691)   ← 窗口右边缘（排除）
```

### 换算结果

| 项 | 物理 | 比例 = 物理/692 或 /1524 | 341×751 窗口下逻辑坐标 |
|---|---|---|---|
| 文字左 | 257 | 0.37139 | 126.6 |
| 文字右 | 430 | 0.62139 | 211.9 |
| 文字上 | 1416 | 0.92913 | 697.7 |
| 文字下 | 1434 | 0.94094 | 706.6 |
| 中心 | (343.5, 1425) | (0.49639, 0.93504) | (169.3, 702.2) |

**屏幕绝对坐标**（窗口在 `(0,31)`）= 窗口内坐标 + `(0, 31)`：
中心 ≈ **(169, 733)**

### 监控区建议（留边距）

```
相对比例  x: 0.34 ~ 0.66   (宽 0.32)
          y: 0.915 ~ 0.955 (高 0.04)
```
341×751 窗口下 → 屏幕区域起点约 `(116, 718)`，尺寸 `109×30` 逻辑点。

> ⚠️ 窗口截图是**按矩形 frame** 截的，会把圆角外的桌面内容一起截入（左侧 x<28、右侧 x>660 的亮像素就是桌面）。
> 因此比例基准必须用**整个窗口 frame 的宽高**，不能用「可见手机屏幕」的宽高。

## 6. 已发现的状态：镜像断开

实测中镜像自己断开了，窗口显示：

```
iPhone 使用中
因 iPhone 被使用，iPhone 镜像已结束。
锁定 iPhone 以连接。
[ 连接 ]
```

这是必须识别的第三态，否则程序会静默空转。

（推测触发原因：iPhone 端被解锁/被操作，镜像被系统主动终止。）
