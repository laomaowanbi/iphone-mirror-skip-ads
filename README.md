## 0. v2.0 相对 v1.0 改了什么

1. **取帧改用 ScreenCaptureKit 采集器**（`bin/sck_grab`，源码 `bin/sck_grab.swift`）。
   旧版用截图类 API（`CGDisplayCreateImageForRect`）读镜像画面，iPhone 端会收到一次
   「用户截图了」事件→ iOS 广播给红果 → 不断弹「已截取纯净页面 / 识图找同款」浮窗
   （每集 ≈ 320 次）。改成 SCStream 帧回调（录屏流采集语义）后实测**零截图事件**。
   采集器不在时自动回退旧截图路径（功能照旧但会弹浮窗，日志会警告）。
2. **误滑进商品页自动点左上角返回**：广告上滑有时进了**抖音商城商品页**（详情页 /
   视频图集页）而不是正片。现在用 OCR 判「还在商品生态」（强特征词 1 个、或弱特征词 2 个），
   用**纯白像素质心**动态定位左上角「<」（写死坐标必偏），**最多连点 3 次**（商品生态多层），
   点不出则存证 + 冷却 60 秒交给用户手动。
3. **可双击的 App**：`bash scripts/make_app.sh` 一键生成 `~/Applications/iPhone镜像去广告.app`
   （防双开靠 `logs/app.pid` + `kill -0`，不用 `pgrep -f`——它会误命中任意命令行含
   `src/app.py` 的进程）。
4. **菜单栏图标改成媒体按钮语义**：在跑时显示 `⏸`（点它就暂停）、停下时显示 `▶︎`
   （点它就开始）；**左键直接切换监控，右键弹菜单**。
   坑：PyObjC 没暴露 `NSStatusBarButton.setSendActionOn_`（button 与它的 cell 都没有），
   调一下就报 `AttributeError` 并静默中断 `buildMenu`；右键只能靠
   `NSEvent.addGlobalMonitorForEventsMatchingMask_handler_` 实现。
5. **版本号集中一处**：`src/app.py` 里的 `VERSION`；App 的 `CFBundleShortVersionString`
   由 `scripts/make_app.sh` 自动读它，不会两边不一致。

## 1. 一句话目标

在 macOS 上监控 **iPhone 镜像 app** 里红果短剧播放时的广告页，检测到「上滑继续看短剧」就自动用**鼠标滚轮上滚**把广告滑走，让短剧不中断。

---

## 2. 背景与痛点

用户用 iPhone 镜像 app 在 Mac 上看红果短剧。**每一集结束都会弹出广告**，需要人工把鼠标移到窗口底部「上滑继续看短剧」的位置、滚轮往上滚，才能跳过广告继续看。

一集一集重复，极其打断。目标是把这个动作自动化。

**为什么不能直接改红果 App / 装插件**：手机端 App 无法改，也不打算越狱/注入。只能在「镜像窗口」这个外部层面用鼠标事件模拟，这也决定了技术路线。

---

## 3. 范围

### ✅ 做（MVP）

1. **菜单栏 app**（主入口）：点「开始监控」/「停止监控」，图标状态可见
2. **启动自检**：iPhone 镜像 app 是否在运行、镜像是否真的连着
3. **窗口定位**：把镜像窗口移到固定位置（左上角），尺寸按实际读取
4. **广告检测**：每 3 秒只截「上滑继续看短剧」那一小块区域，模板匹配判断
5. **自动跳过**：命中 → 鼠标移到该坐标 → 滚轮上滚 → 鼠标移回原位
6. **三态识别**：广告页 / 播放中 / 镜像断开，分别处理（不把断开当播放）

### ⏸ 暂不做

- 语音口令「开始去广告」（预留接口，后续接 `voice-system`）
- 自动重连断开的镜像（先只提示，不自动点「连接」）
- 上滑失败后的重试策略（先做一次成功的，再谈兜底）
- 全屏/多窗口/其他 App 的广告拦截

### 🚫 明确不做

- 不修改红果短剧 App、不抓包、不破解会员
- 不做全屏 OCR 扫描（性能浪费，需求已明确否定）

## 4. 核心设计

### 4.1 启动流程

```
用户点「开始监控」
  ↓
① 检测 iPhone 镜像 app 是否运行（bundle: com.apple.ScreenContinuity）
   └─ 没运行 → 提示「请先打开 iPhone 镜像」→ 不启动
  ↓
② 读取窗口 AX frame，尝试把窗口移动到固定位置 (0, 菜单栏高度≈30)
   └─ 移动失败（权限/系统限制）→ 降级为「每次读实时 frame 用比例换算」
  ↓
③ 校验镜像是否真的连着
   ├─ 连着 → 正常进入监控循环
   └─ 断开（「iPhone 使用中…锁定 iPhone 以连接」）→ 提示用户，不空转
  ↓
④ 采集模板（首次运行）：从当前广告页截「上滑继续看短剧」存为模板图
  ↓
进入监控循环（每 3 秒）
```

### 4.2 监控循环（状态机）

```
        ┌──────────────────────────────────────┐
        │  每 3 秒：截「上滑继续看短剧」区域   │
        │  （约 85×24 逻辑点 / 170×48 像素）   │
        └──────────────┬───────────────────────┘
                       ↓
              ┌────────────────┐
              │ 区域特征判断    │
              └────────┬───────┘
        ┌──────────────┼──────────────┐
        ↓              ↓              ↓
    ┌────────┐   ┌──────────┐   ┌──────────────┐
    │ AD     │   │ PLAYING  │   │ DISCONNECTED │
    │有这几个字│   │    无    │   │ 黑屏/连接页  │
    └───┬────┘   └────┬─────┘   └──────┬───────┘
        ↓              ↓                ↓
   鼠标移到坐标      什么都不做      菜单栏图标变红
   滚轮上滚         继续下一轮      提示「镜像已断开」
   鼠标移回原位     (倒计时也走这条)
        ↓
   等比退避 1.5s 后再检测
   （避免重复滚动/滚动动画未完成）
```

**为什么必须三态**：实测已遇到镜像断开页。若只做「有字/没字」二分，断开态会被当成 PLAYING，程序静默空转，用户以为在工作其实没有。

### 4.3 判断「有没有这几个字」——双层判据

**不能只靠亮度**（短剧画面也可能黑底），**也不能全图 OCR**（慢且没必要）。方案：

1. **粗筛（微秒级）**：区域亮度均值 + 灰色文字像素占比
   - 广告页特征：背景近纯黑（RGB 各通道 < 25）+ 存在一批中灰像素（100~170）构成文字
   - 不满足 → 直接判 PLAYING，跳过模板匹配
2. **确认（毫秒级）**：模板匹配（numpy 归一化互相关，NCC > 0.8 判命中）
   - 模板从首次遇到的广告页采集，存 `assets/template_ad_text.png`
   - 归一化到固定尺寸后比对，容忍 ±1px 抖动和轻微缩放

**双保险**：粗筛只为省时间，模板匹配才是判定依据，避免误滚。

## 5. 已实测确认的技术事实

全部为**本机实测**，不是推测。详见 `docs/技术实测数据.md`。

| 项 | 结果 |
|---|---|
| app 名称 / bundle | `iPhone镜像` / `com.apple.ScreenContinuity` |
| 窗口读写权限 | `AXIsProcessTrusted = True`（辅助功能权限已授予） |
| **Position 可写** | ✅ 是；目标 `(0, 30)` 实际落到 `(0, 31)` |
| **Size 可写** | ⚠️ 名义可写，但**系统会重算**：设 346×762 结果变 341×751。<br>**结论：不改尺寸，只固定位置，坐标按比例换算** |
| 屏幕 / 菜单栏 | 逻辑 2048×858；菜单栏 **30pt**；visibleFrame 高 752 |
| 窗口宽高比 | 0.4541（iPhone 镜像锁比例，缩放时保持） |
| 截图性能 | `screencapture -R` 小区域 **~98ms**；<br>`CGDisplayCreateImageForRect` **~28ms**（快 3.5×）→ 采用后者 |
| 滚轮模拟 | `CGEventCreateScrollWheelEvent` + `kCGScrollEventUnitPixel` ✅ 可用 |
| 鼠标定位 | `CGWarpMouseCursorPosition` ✅ 可用 |
| Python 环境 | `~/Projects/mcp/.venv/bin/python`（已含 pyobjc / PIL / numpy） |

### 「上滑继续看短剧」坐标（关键数据）

基准：窗口 346×762 逻辑点，窗口截图为 692×1524 物理像素（2.0×）。

| 项 | 物理像素 (692×1524) | **相对比例** | 在 341×751 窗口下 |
|---|---|---|---|
| 文字左边界 | x = 257 | **0.3714** | x ≈ 126.7 |
| 文字右边界（含 ⌃） | x = 430 | **0.6214** | x ≈ 211.9 |
| 文字上边界 | y = 1416 | **0.9291** | y ≈ 697.8 |
| 文字下边界 | y = 1434 | **0.9410** | y ≈ 706.7 |
| **点击中心** | (343.5, 1425) | **(0.4964, 0.9350)** | **(169.3, 702.2)** |

**建议监控区**（留边距，避免边界抖动漏检）：

```
相对比例   x: 0.34 ~ 0.66    (宽 0.32)
           y: 0.915 ~ 0.955  (高 0.04)
→ 341×751 窗口下即屏幕区域  约 (116, 687) 起，109×30 逻辑点
```

> ⚠️ 这套坐标基于「窗口 frame 的矩形」量出。窗口截图会连圆角外的桌面一起截进来，按 frame 矩形算比例是一致的，不要按「手机屏幕圆角区」算。

## 6. 技术选型

| 模块 | 选型 | 理由 |
|---|---|---|
| 菜单栏 UI | **pyobjc 原生 `NSStatusItem`** | 项目 venv 已有 pyobjc；`rumps` 未装在该 venv，且 rumps 底层就是 NSStatusItem，没必要多引依赖 |
| 窗口操作 | `ApplicationServices`（AXUIElement） | 已实测可读可写，无需 AppleScript 的额外权限弹窗 |
| 截图 | `Quartz.CGDisplayCreateImageForRect` | 28ms，比爬 `screencapture` 进程快 3.5×，无进程开销 |
| 图像判定 | `numpy` NCC 模板匹配 + 亮度粗筛 | 无依赖、无网络、确定性 |
| 鼠标/滚轮 | `Quartz.CGEvent*` | 系统级事件，iOS 镜像窗口能接收 |
| 暂停/节流 | `time.sleep` + 状态退避 | 简单可靠，无需线程池 |

## 7. 已知坑与风险

| # | 风险 | 应对 |
|---|---|---|
| 1 | **窗口尺寸会被系统重算** | 不改尺寸，只固定位置；坐标一律走相对比例 |
| 2 | **窗口被其他 app 遮挡 → 截到别人的内容** | 启动时把镜像窗口拉最前；连续 N 次检测不到时复核窗口层级，别误判 |
| 3 | **镜像断开（已实测遇到）** | 三态识别，独立提示，不空转 |
| 4 | **滚轮方向可能反** | 「上滑」= 滚轮向上还是向下需实测确认；代码里做成常量 `SCROLL_UP_SIGN`，一改即生效 |
| 5 | 鼠标被移走影响用户 | 记录原位 → 移过去 → 滚 → **移回原位** |
| 6 | 广告有 5 秒倒计时 | 倒计时期间检测不到文字 → 走 PLAYING 分支自然等待，不误操作 |
| 7 | 重复滚动 | 滚完退避 1.5s 再检测，避免连滚 |
| 8 | iPhone 镜像窗口最小尺寸限制 | 移动位置实测有效；尺寸不动，规避该限制 |
| 9 | 屏幕录制权限 | `screencapture` 已能成功截图，权限已具备；若换机需重新授权 |

## 11. 日志与诊断（出问题了看这里）

### 文件位置

| 文件 | 内容 | 轮转 |
|---|---|---|
| `logs/ad_monitor.log` | 全量运行日志（含 DEBUG 级 tick） | 5MB × 5 份 |
| `logs/errors.log` | **只有 WARNING / ERROR**，排查先看这个 | 2MB × 3 份 |
| `logs/shots/` | 存证截图，最多保留 200 张，超出自动删最旧 | — |

### 每条日志能查到什么

| 场景 | 日志长什么样 |
|---|---|
| 启动 | `启动 环境={'screen':'2048x858','window':'(0,30) 341x751','ratio':0.45406,'monitor_box':(...),'template':'220x60','thresholds':'mean<60.0 text_px>=300 ncc>=0.7','scroll':'sign=-1 pixel=300 steps=4'}` |
| 菜单动作 | `状态 idle → watching` |
| 正常轮询 | `DEBUG core: tick #37`（只进文件，不刷终端） |
| **命中广告** | `AD 命中 {'mean':14.8,'text_px':1058,'ncc':0.837} → 跳过 (169, 733) 存证=20261127-145648_adhit_ncc0.837_001.png` |
| 跳过成功 | `跳过成功 → PLAYING 画面亮度=75.9` |
| **跳过失败** | `跳过可能失败 → AD 画面亮度=15.2 存证=20261127-150102_ADFAIL_fullwindow_003.jpg`（**整窗截图**） |
| 窗口被移动/缩放 | `窗口变化 (0,30,341,751) → (2,30,346,762) (环境: {...新坐标...})` |
| 镜像断开 | 状态变 `disconnected`，菜单栏图标 `⚠︎`，提示「锁定 iPhone 后点连接」 |
| 异常 | `tick 异常` + 完整 traceback（只走 errors.log） |

### 存证截图的意义

- **误判广告**（不该滚却滚了）→ 看 `adhit_*.png`，能看到当时监控区到底是什么
- **漏检广告**（该滚没滚）→ 如果日志里根本没有 `AD 命中`，说明是判定阈值问题，需要拿当时的画面标定
- **跳过失败** → 看 `ADFAIL_fullwindow_*.jpg`，能看清是滑错方向、还是根本没滚、还是镜像断开了

### 文件名标签含义

| 标签 | 何时产生 |
|---|---|
| `adhit_nccXXXX` | 判定为广告时，监控区小图（约 3.5KB PNG） |
| `ADFAIL_fullwindow` | 跳过失败时，**整个镜像窗口**（约 88KB JPEG，0.75× 缩放） |

### 快速排查命令

```bash
cd ~/projects/iphone镜像去广告

# 最近出过什么错
cat logs/errors.log | tail -30

# 今天跳了几次广告
grep -c "AD 命中" logs/ad_monitor.log
grep "跳过成功\|跳过可能失败" logs/ad_monitor.log | tail -10

# 窗口有没有乱跑
grep "窗口变化" logs/ad_monitor.log

# 打开存证看现场
open logs/shots/
```
